# Starter Application Code Review (`app/main.py`)

## 1. Identified and Resolved Defects

| # | Location | Defect Description | Reproduction / Symptom | Fix Implemented |
| :- | :--- | :--- | :--- | :--- |
| 1 | `app/main.py` — Environment initialization | `load_dotenv(override=True)` (or hardcoded fallback values) allowed `.env` values to overwrite process environment variables `MONGO_URI` and `MONGO_DB`. | Running tests with `MONGO_DB=attendance_test pytest` still connected to the database defined in `.env`. | Called `load_dotenv(override=False)` and read `os.environ.get("MONGO_URI")` and `os.environ.get("MONGO_DB")` dynamically. |
| 2 | `GET /health` (`health_check`) | Returned a static `{"status": "ok"}` dictionary without querying MongoDB. | Stop MongoDB and call `GET /health`; endpoint falsely returned `HTTP 200` instead of `HTTP 503`. | Executed `db.command("ping")` inside a `try/except` block, returning `HTTP 200` on success and `HTTP 503` when MongoDB is unreachable. |
| 3 | `POST /employees` (`create_employee`) | Missing `^EMP\d{4,6}$` regex check, allowed `shift_start == shift_end`, stored `created_at` as raw epoch/naive datetime, and used non-atomic `find_one` + `insert_one` without a unique index. | Two concurrent `POST /employees` requests with `"emp_code": "EMP0001"` both passed `find_one` and inserted duplicate employee documents. | Enforced Pydantic v2 validators (`^EMP\d{4,6}$`, `shift_start != shift_end`, email normalization), stored `created_at` as truncated UTC BSON `datetime`, created unique index `idx_emp_code_unique`, and caught `DuplicateKeyError` to return `HTTP 409`. |
| 4 | `GET /employees` (`list_employees`) | Loaded all employee documents into Python memory before slicing and calculated `total` as the unfiltered collection count. | Calling `GET /employees?department=Sales&page=1&page_size=5` returned `total` equal to all employees across all departments and performed an in-memory scan. | Executed `count_documents(query)` with the department filter and chained `.find(query, {"_id": 0}).sort("emp_code", 1).skip(skip).limit(page_size)` inside MongoDB. |
| 5 | Timestamp parsing & serialization (Section 10 & Rule R1) | Accepted string timestamps, floating-point timestamps, and seconds-based timestamps, and failed to truncate milliseconds to whole seconds before storage and shift calculations. | Passing `"punched_at": "1735788600000"` or `"punched_at": 1735788600.5` was coerced instead of rejected with `422`; sub-second ms caused 1-second drift against `shift_start`. | Added `validate_strict_epoch_ms` rejecting `bool`, `float`, `str`, and values outside `[946684800000, 4102444800000]`, and truncated all instants via `(ms // 1000) * 1000` before conversion to UTC `datetime`. |
| 6 | Attendance date & overnight shift calculation (`compute_attendance_date_ist`, Rule R1) | Computed attendance date using UTC calendar date instead of IST (`UTC+05:30`) and failed to attribute pre-`shift_end` overnight punches to the previous IST calendar date. | A punch-in at `2025-01-03T01:30:00+05:30` for an overnight shift (`22:00`–`06:00`) was recorded under `2025-01-03` instead of `2025-01-02`. | Converted `punch_in` to IST (`UTC+05:30`), detected overnight shifts via `shift_end <= shift_start`, and subtracted 1 day when `ist_time < shift_end`. |
| 7 | Late arrival calculation (`compute_late_minutes`, Rule R2) | Used `>= 10` minutes or `math.ceil(elapsed_seconds / 60)`, marking arrival at exactly 10 minutes (`600s`) as late or inflating 10m 1s (`601s`) to 11 minutes. | Punching in at `09:10:00` for a `09:00` shift returned `late_minutes = 10` instead of `0`; punching in at `09:10:01` returned `0` or `11` instead of `10`. | Checked `elapsed_seconds <= 600` (returning `0` within the 10-minute grace period) and returned `int(math.floor(elapsed_seconds / 60))` when `elapsed_seconds > 600`. |
| 8 | `POST /attendance/punch-in` concurrency | Used a non-atomic `find_one` followed by `insert_one` without a unique compound index on `(emp_code, date)`. | Firing two simultaneous `POST /attendance/punch-in` requests for the same employee and shift date produced two `HTTP 201` responses or an unhandled `500` error. | Created unique compound index `idx_emp_date_unique` on `(emp_code, date)` and performed a direct atomic `insert_one`, translating `DuplicateKeyError` into `HTTP 409`. |
| 9 | `POST /attendance/punch-out` lookup, overnight shift window & concurrency | Looked up open attendance records only on `punched_at`'s calendar date, ignored overnight shift end dates (+1 day), and updated via non-atomic `update_one`. | Punching out at `06:15` IST the next morning for a `22:00`–`06:00` shift returned `404`; concurrent punch-outs both returned `HTTP 200`. | Queried the most recent record with `punch_in <= punched_at` sorted by `punch_in DESC`, enforced `0 < duration <= 86400s`, added 1 day to `shift_end` for overnight shifts, and used atomic `find_one_and_update({"_id": record["_id"], "punch_out": None})`. |
| 10 | Overtime, half-up rounding & half-day order of operations (Rules R3, R4, R5, R8) | Used Python's banker's rounding `round(val, 2)` instead of `ROUND_HALF_UP`, counted `< 30` minutes as overtime, and evaluated `half_day = raw_hours < 4.5` before rounding `work_hours`. | A shift lasting `16182` seconds (`4.495` hours) rounded to `work_hours = 4.50` but still set `half_day = True`. | Implemented `round_half_up` with `Decimal` and `ROUND_HALF_UP`, evaluated `half_day = work_hours < 4.50` strictly after rounding `work_hours`, and zeroed `overtime_minutes` when whole post-shift minutes `< 30`. |
| 11 | `GET /attendance` filtering, sorting & `_id` serialization | Did not reject `date_from > date_to` with `422`, omitted secondary sort `emp_code ASC`, and leaked `ObjectId` or unserialized BSON `datetime` objects. | Calling `GET /attendance?date_from=2025-01-10&date_to=2025-01-01` returned `200 []` instead of `422`; ties on `date` had non-deterministic order. | Validated `date_from <= date_to`, sorted by `[("date", DESCENDING), ("emp_code", ASCENDING)]`, excluded `_id`, and converted all timestamps (including nested `history`) to integer epoch ms. |
| 12 | `PATCH /attendance/{emp_code}/{date}` regularization & audit history | Allowed client-supplied derived fields, failed to clear punches when setting `ABSENT`/`LEAVE`, recorded unchanged fields in `history.changes`, left nested history timestamps as `datetime`, and overwrote concurrent edits. | Submitting a PATCH with unchanged `status` still appended a history entry; concurrent PATCH requests silently lost one audit entry. | Used `extra="forbid"`, recalculated all derived fields, verified `punch_in` remains on `date` under R1, recorded only changed fields in `history.changes`, serialized nested `from`/`to` timestamps to epoch ms, and used an atomic conditional `find_one_and_update` matching prior state and `history` size (`HTTP 409` on conflict). |
| 13 | Analytics endpoints (`monthly`, `department_summary`, `late_leaderboard`, `department_trend`) & `/admin/explain` | Computed analytics via Python loops over `find()`, derived department headcount from `attendance_logs` (omitting 0-log employees), ranked leaderboard by array index and truncated ties at `limit`, generated trend dates in Python, and lacked indexes causing `COLLSCAN`. | Employees with zero attendance logs were missing from department `headcount`; tied ranks at cutoff `limit` were dropped; `/admin/explain` showed `COLLSCAN`. | Rewrote all four analytics endpoints as pure MongoDB 6.0+ aggregation pipelines (`$lookup` from `employees`, `$setWindowFields` with `$rank` and post-rank `rank <= limit` filter, `$densify` + `$setWindowFields` 7-day moving average, `Decimal128` half-up rounding) backed by targeted compound indexes (`IXSCAN`). |

## 2. Inspected Code Determined Not to Be Defective

1. **Synchronous PyMongo Architecture**: Using synchronous `pymongo.MongoClient` with FastAPI `def` route handlers (which FastAPI runs safely in an external threadpool) is completely valid and avoids mixing event-loop blocking calls inside `async def` coroutines.
2. **Route Path Signatures and Query Parameter Naming**: The endpoint URL templates (`/health`, `/employees`, `/attendance/punch-in`, `/attendance/punch-out`, `/attendance`, `/attendance/{emp_code}/{date}`, `/analytics/employees/{emp_code}/monthly`, `/analytics/departments/summary`, `/analytics/leaderboard/late`, `/analytics/departments/{department}/trend`, and `/admin/explain/{endpoint}`) and pagination envelope keys (`items`, `total`, `page`, `page_size`) already matched `openapi.yaml`.
3. **Attendance Status Enumeration Values**: The five canonical status codes (`PRESENT`, `WFH`, `ON_DUTY`, `ABSENT`, `LEAVE`) and their classification into presence (`PRESENT`, `WFH`, `ON_DUTY`) vs non-presence (`ABSENT`, `LEAVE`) statuses were accurate and preserved.
